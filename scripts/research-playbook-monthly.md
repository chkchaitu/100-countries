# Refresh pass: profiles, how to apply, health, currency, travel alerts

Repo ~/build/100-countries-site. The weekly job covers visa rules and the daily job covers news. This pass reviews everything else for a rotating set of countries, so each country is rechecked about every 10 months (10 countries per run, runs on the 1st and 15th).
Do all research YOURSELF in this one turn, one country after another. Do NOT spawn subagents: a scheduled run cannot wait for them and ends early.

1. `cd ~/build/100-countries-site && git checkout main && git pull -q`
2a. READER SUGGESTIONS: /tmp/suggestions.json (written by the picker) holds new anonymous reader edits (country, section, what changed, official source link, how they know). Each one is a LEAD, never a fact. For every country with a suggestion, open the reader's link, then find the official page yourself, and verify before changing data. Decide per suggestion: CONFIRMED, PARTLY, CANNOT VERIFY or REJECT (spam, wrong country, personal data). Do the suggested check together with that country's normal checks below. Append every processed suggestion to data/suggestions-log.json as {responseId, date, country, section, verdict, officialUrl} with NO personal details and no reader text copied. Mention confirmed ones in the PR body ("reader suggestion") and in the final message.
2. `python3 scripts/pick_refresh.py` and read /tmp/refresh.json (the 10 countries whose oldest `lastChecked` across countries.json, apply.json and health.json is the stalest).
3. For each picked country, check against OFFICIAL sources first (government, embassy, tourism board, WHO, CDC):
   - Profile (data/countries.json): entry or attraction fees and opening status, seasonal closures, best months for low budget, transport, safety advisories (India's MEA advisory, tourism board), gone experiences. Currency name, code and symbol still correct.
   - How to apply (data/apply.json, only if the country needs a visa): apply links still open (curl -sIL -m 20), forms, documents, photo spec, fee, processing time, centres, whether the route changed (for example a new e-visa portal or a suspended service). Drop dead links, add the new official link.
   - Health (data/health.json): yellow fever entry rule from India, required and recommended vaccines, malaria, new health notices (CDC, WHO, the destination health ministry). If a country is added to or removed from India's yellow fever or polio lists, update data/health-global.json.
   - Transit (data/transit.json): airside and landside transit rules for Indians, transit schemes (96-hour, 72-hour, tour transit), which valid visas waive the transit visa, any new airport transit visa requirement; check the official immigration or foreign ministry page first.
   Items you cannot confirm stay UNVERIFIED. Never guess. Plain English, no em dashes, no personal data.
3b. TRAVEL ALERTS (data/alerts.json, all 195 countries): first, for EVERY alert already in the file, check its official source again (MEA https://www.mea.gov.in, the Indian embassy for that country, the airline's own notice) and decide: still active (update summary, `until`, `lastChecked`), or LIFTED (delete the entry, and say so in the PR body with the date). Then, for each picked country, look for a NEW active item that affects an Indian passport holder: an MEA or Indian embassy advisory, an airline suspension of India routes, an entry ban or closure, a border closure. Add it with id, country, type (flights, advisory, entry, closure, other), severity (high or medium), title, summary in plain English, since, until (empty if open ended), lastChecked, sourceLevel and sources. sourceLevel is "official" only if you read the official page; otherwise "news", and say so. Never delete an alert only because it is old: remove it only when an official or clearly dated source says it is lifted. Keep the summary factual, no advice beyond what the source says, no em dashes.
4. Update the files, set `lastChecked` to today for every country you really checked, fix `sources` and `confidence`. If you could not check a country properly, leave its `lastChecked` unchanged and list it as "not done".
5. Write the PR body to /tmp/pr-body.md (per country: what changed, old and new value, source links). Run `python3 scripts/check_data.py` (must pass), then `scripts/finish_pr.sh "Refresh pass YYYY-MM-DD" /tmp/pr-body.md`. It branches, opens the PR, waits for the check and merges. If there are no changes, do not run it.
6. Never end the turn waiting for anything. The run counts as a success only if finish_pr.sh printed MERGED, or you honestly found nothing to change after really checking every picked country.
7. Final reply to WhatsApp (plain text, no tables, no em dashes): travel alerts added, updated or lifted; changed (country, what, source link), confirmed unchanged (count and names), could not verify, dead links removed, countries not done.
